# ActType、角标位置，与一处需要撤回的说法

> 2026-11-02 12:07。本文含三类内容，**标记清楚**：
> **[文]** 用户口述的机制（无代码证据） / **[测]** 实测 / **[码]** 代码。

---

## 1. 机制（用户口述，[文]）

- 每回合 NPC / 支援卡会随机刷新 buff
- 但**剧本机制优先**：剧本 link 与对应卡所放的位置，触发对应的 buff
- **buff 不会出现在不对应的位置**

⇒ 角标位置不是装饰，它**承载"这张卡这个位置 → 这个 act"的对应关系**。

---

## 2. 撤回我上一轮的说法

我上一轮写过：

> `ACT_GAUGE_GAIN_BADGE_POSITION_*` 是 `Vector2`，是**纯 UI 坐标，与增量无关**。

**"与增量无关"这句撤回。**

字段类型确实是 `Vector2`（坐标），但它编码了 **ActType 的方位语义**，
是理解「link + 卡位置 → buff 归属」的入口，**不是可丢弃的噪声**。

教训与之前 `GAIN` 字段名那次相反：那次是**拿名字当语义**，
这次是**拿类型当结论**。两个方向都会错。

## 3. `ActType` 实测：**只有 5 个成员** **[测]**

`/debug/dumpclass?name=ActType`：

| 成员 | 类型 |
|:--|:--|
| `value__` | `System.Int32` |
| `ActType01` | `ActType` |
| `ActType02` | `ActType` |
| `ActType03` | `ActType` |
| `ActType04` | `ActType` |
| `ActType05` | `ActType` |

**5 个成员。**

⚠️ **成员的具体数值没有拿到** —— 枚举字面量在 dump 里偏移为 0（静态字面量，不占实例布局），
该端点不返回字面量值。所以「`ActType01` = 1」目前是 **[无证]**。

## 4. 一个必须记下的数字矛盾

| 来源 | 数量 |
|:--|:-:|
| `ACT_GAUGE_GAIN_BADGE_POSITION_*` 字段 | **7** |
| `ActType` 枚举成员 | **5** |

7 个位置：`HOLIDAY` / `OUTING` / `OUTING_SUMMER` / `HOSPITAL` / `RACE_NORMAL` / `RACE_RESERVE` / `RACE_ROUTE`

**7 ≠ 5** ⇒ 位置与类型**不是一一对应**。

可能形态（**未验证**）：比赛拆 3 个位置、外出拆 2 个位置，其余各 1 个；
或某些位置不绑定 act 类型。

**在拿到 ActType 数值前，不能把 `ActType01..05` 硬绑到 HOLIDAY/HOSPITAL/... 上。**
