# 演目 buff 的绑定对象：支援卡，不是训练项目

> 2026-11-02 12:10 用户口述机制。**这是机制定义，不是代码证据**，全文标 **[文]**。
> 它直接改变我们对 `ActType` / 角标位置 / 增量字典的判读方式。

---

## 1. 规则原文含义（[文]）

1. **角标常亮，跟着支援卡走。** buff 绑的是**卡**，不是训练种类。
2. **卡放哪，buff 就在哪。**
   例：buff 挂在速度卡上；速度卡被放到**力量训练** ⇒ buff 出现在**力量训练**。
3. **稽古触发会抢位。**
   例：速度训练触发稽古 ⇒ 稽古把「人头」抢过来 ⇒ 卡与 buff 都归到速度训练，别的训练上没有这个 buff。
4. **非对应位置 ≠ 不能去。** 卡可以放在任意训练上，buff 跟随；没有「buff 只在指定训练生效」这回事。

---

## 2. 这修正了什么

| 我此前的理解 | 实际 |
|:--|:--|
| 角标位置 = ActType 固定方位 | 位置只是**默认显示方位**；真实归属随卡移动 |
| 位置与训练项目绑定 | **不绑定**，卡在哪个训练就跟随到哪 |
| 位置字段可用来反推 ActType | **不行** —— 位置是显示坐标，归属由卡实例决定 |

---

## 3. 对解密的具体影响

| 项 | 影响 |
|:--|:--|
| `TrainingCommandEntity._gainActGaugeAmountDict` | 键是 `ActType`，值是**该条训练命令当下**的增量；卡一挪，同一 ActType 的增量就换到别的命令上 |
| 两次采样对比 | **必须先确认卡的位置没变**，否则差异根本不是时间差，是位置差 |
| 稽古那一帧 | 卡的归属被强改，**不能当常规采样点** |
| 内存里找固定映射表 | 若表是 `ActType → 增量`，它是**常量**；若是 `命令 → 增量`，它是**派生值**。本轮之前一直按后者找 |

---

## 4. 一个新的可验证预测

若 buff 绑卡：

> 把挂 buff 的支援卡从 A 训练挪到 B 训练，**协议里 A 的那条 command 的增量应消失，B 的那条应出现同值增量**。

这条可以用**两次协议对比**直接验证，不需要反汇编。

**这是目前最省力的验证路径。**
